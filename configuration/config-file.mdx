Jetic stores all of its project-level settings in a `.jetic/` directory at the root of your project. The primary file in that directory is `config.json`, which tells Jetic which AI provider to use, which model to call, and where to find your API key. Running `jetic init` creates this directory and populates `config.json` for you, but you can also edit the file directly or update it with `jetic config ai`.

## Location

Jetic always looks for `.jetic/config.json` relative to your current working directory. Make sure you run all `jetic` commands from your project root — the same directory that contains your `tsconfig.json`.

```
my-express-app/
├── .jetic/
│   ├── config.json      ← AI configuration
│   ├── model.json        ← generated by jetic scan
│   ├── workflow.json     ← generated by jetic simulate workflow
│   └── memory.json       ← runtime memory store
├── src/
├── tsconfig.json
└── package.json
```

## Full Schema

Below is a complete `config.json` example showing every supported field:

```json
{
  "ai": {
    "provider": "openrouter",
    "model": "meta-llama/llama-3.1-8b-instruct",
    "apiKeyEnvVar": "OPENROUTER_API_KEY"
  }
}
```

### Field Reference

<ParamField body="ai" type="object">
  The AI configuration block. This entire object is optional — if omitted, Jetic performs static route discovery without AI-powered parameter extraction.
</ParamField>

<ParamField body="ai.provider" type="string" required>
  The AI backend to use for schema extraction and workflow generation. Accepted values:

  - `"openai"` — Use the OpenAI API directly.
  - `"openrouter"` — Use OpenRouter to access a wide range of models from a single API.
</ParamField>

<ParamField body="ai.model" type="string" required>
  The model identifier to pass to the selected provider. Examples:

  - `"gpt-4o"` (OpenAI)
  - `"gpt-3.5-turbo"` (OpenAI)
  - `"meta-llama/llama-3.1-8b-instruct"` (OpenRouter)

  The default when running `jetic init` with no input is `meta-llama/llama-3.1-8b-instruct`.
</ParamField>

<ParamField body="ai.apiKeyEnvVar" type="string" required>
  The **name** of the environment variable that holds your API key — not the key value itself. Jetic reads `process.env[apiKeyEnvVar]` at runtime. For example, if you set `"apiKeyEnvVar": "OPENAI_API_KEY"`, Jetic looks for `process.env.OPENAI_API_KEY`.

  When you run `jetic init` and enter a provider name, Jetic automatically sets this to `<PROVIDER_UPPERCASE>_API_KEY` (e.g., `OPENROUTER_API_KEY`).
</ParamField>

## Generated Files

Running Jetic commands creates and updates the following files inside `.jetic/`:

| File | Created by | Purpose |
|---|---|---|
| `config.json` | `jetic init` or `jetic config ai` | Stores AI provider, model, and API key env var name |
| `model.json` | `jetic scan` | The versioned Behavioral Model — all discovered endpoints, parameters, middleware, and dependencies |
| `workflow.json` | `jetic simulate workflow` | The AI-generated workflow definition used for multi-step execution |
| `memory.json` | `jetic simulate workflow` | Runtime key-value store; holds tokens and values captured during a workflow run |

<Note>
  `model.json` is safe to commit to version control. It contains no secrets — only structural metadata about your API. `memory.json` may contain captured tokens from test runs, so consider adding it to `.gitignore`.
</Note>

## Environment Variables

Jetic never stores API key values inside `config.json`. Instead, it reads the key from the environment variable named in `apiKeyEnvVar`. Create a `.env` file at your project root to supply this value:

```bash .env
OPENROUTER_API_KEY=sk-or-...
```

```bash .env
OPENAI_API_KEY=sk-...
```

When `jetic init` prompts for your API key and you enter a value, it appends the key to your `.env` file automatically. Jetic uses `dotenv` to load `.env` before any command runs.

<Warning>
  Add `.env` to your `.gitignore` immediately. Never commit API keys to version control.
</Warning>

## Viewing Your Current Config

<Note>
  Run `jetic config` at any time to print your current configuration as a formatted table — including the project root, Jetic directory path, AI provider, model name, and API key environment variable name.
</Note>

<Tip>
  To update your AI provider or model after initial setup, use `jetic config ai` instead of re-running `jetic init`. For example:

  ```bash
  jetic config ai --provider openai --model gpt-4o --key-env OPENAI_API_KEY
  ```

  This overwrites only the `ai` block in `config.json` without touching your model or memory files.
</Tip>
