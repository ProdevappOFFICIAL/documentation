`jetic simulate endpoint` takes the endpoint schemas stored in your Behavioral Model and turns them into real HTTP requests against your live server. Jetic generates realistic request data from the schema — including body fields, path parameters, and headers — then validates the response against the expected shape. Use it to quickly verify a single route or run a full sweep across every endpoint at once.

## Usage

```bash
jetic simulate endpoint [method] [path] [flags]
```

## Flags

<ParamField query="--all" type="boolean">
  Simulate every endpoint discovered in `model.json` sequentially. Prints a progress bar and a pass/fail/skipped summary when complete.
</ParamField>

<ParamField query="--verbose" type="boolean" default="false">
  Show full request and response details for each endpoint: generated request body, request headers, response body, and a field-by-field schema validation breakdown.
</ParamField>

## Environment Selection

When you run a simulation, Jetic reads the `environments` array from your `model.json` and presents an interactive picker:

- If **no environments** are defined, Jetic defaults to `http://localhost:3000`.
- If **one environment** is defined, Jetic selects it automatically and prints the base URL.
- If **multiple environments** are defined, use the **↑ / ↓** arrow keys to navigate the list and press **Enter** to confirm your selection.

After picking an environment, Jetic performs a health check against the base URL before sending any simulation requests. If the server is unreachable, the command exits with a clear error message.

Simulate a specific endpoint with full verbose output:

jetic simulate endpoint GET /api/orders/:id --verbose

```bash
jetic simulate endpoint --all
```

<Note>
  Your backend server must be running before you execute `jetic simulate endpoint`. Jetic checks reachability at the selected environment's base URL before sending any requests, and exits early with a descriptive error if the server is not responding.
</Note>

<Tip>
  Define named environments in your `model.json` under the `environments` array — for example, `local`, `staging`, and `production` — each with its own `baseUrl`. This lets you quickly switch targets using the interactive environment picker without editing any files.
</Tip>
